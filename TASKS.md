# Очередность задач

Идём сверху вниз. Не прыгать к моделям, пока нет таксономии по видео.

## Фаза 0 — окружение (блокер)

1. Установить Python 3.12+ (сейчас в системе его нет) и FFmpeg.
2. Создать venv, поставить `requirements.txt`, скопировать `.env.example` → `.env`.
3. Проверить каркас: UI открывается, `POST /api/v1/analyze` + poll `GET /api/v1/jobs/{id}` отдают JSON по схеме жюри.

## Фаза 1 — понять, что искать на видео

4. Просмотреть выборку **с нарушением** и **без** (минимум 8+8 роликов) и выписать, что видно в таймкоде из `data/labels.json`.
5. Собрать черновой каталог типов (3–8 штук) в `app/rules/catalog.json`: визуальный признак, антипример, когда **нельзя** утверждать нарушение.
6. Найти открытые акты РК (adilet.zan.kz / НБРК) и привязать **только** те правила, которые проверяются глазами. Без выдуманных пунктов.
7. Разметить вручную 10–15 роликов: тип + таймкод ±1 с. Это станет внутренним gold set (тип в open_labels нет).

## Фаза 2 — видео-пайплайн без «AI»

Можно параллельно с фазой 1. Подробный бриф: `PHASE2.md`.

8. ~~Извлечение кадров~~ — `app/services/video.py` (`iter_frames`, `frame_at`, `evidence_frames`).
9. ~~JPEG → base64~~ — quality/width в `.env`.
10. ~~LabelAwareStubAnalyzer~~ — `ANALYZER_MODE=labels`, живые кадры, original filename в job. Перед жюри выключить.

## Фаза 3 — локальный детектор

11. Выбрать стек: детекция людей/рук/денег/лотка (локальный YOLO/RT-DETR) + простые временные правила. Лица не идентифицировать. Gold: `python scripts/import_labels.py` + `python scripts/eval_gold_vs_yolo.py`. UI на train: `ANALYZER_MODE=hybrid`.
12. Написать эвристики под найденные типы (пример: посторонний за кассой, купюры вне ящика, касса оставлена без контроля, передача пачки без пересчёта — **только если это реально видно в датасете**).
13. Калибровка порогов на gold set: банк штрафует ложные срабатывания, **пропуск недопустим** — сначала recall по вердикту ролика, потом precision.
14. Тексты `description` и ссылка на правило — шаблоны по типу, не облачная LLM.
15. Проверка на роликах «без нарушения»: если FP много — ужесточить правила, не ослаблять до пропуска.

## Фаза 4 — продукт и сдача

16. Довести UI: статус обработки, вердикт двумя фразами из ТЗ, таймкод, кадры, обоснование, документ+пункт.
17. Стабильность API: ключ, только `.mov`, ошибка `failed`, очистка загрузок, запас по времени < 5 мин.
18. Docker-сборка **со всеми весами внутри**, без сети на инференсе.
19. Публичный URL + ключ жюри.
20. Короткие артефакты сдачи: запуск, архитектура, источники права, список типов, известные ошибки.

## Что не делать

- Не звать GPT/Gemini/Claude и любые облачные vision API.
- Не учить модель на тестовых видео жюри.
- Не писать в `description` то, чего нет на кадре (проводки АБИС, сверка и т.п.).
